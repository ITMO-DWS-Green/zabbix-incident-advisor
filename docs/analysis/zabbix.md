# Анализ аналога: Zabbix

Задача: разобрать ближайший аналог и решить, что берём. Ответственный — Евгений Матеюк. Первоисточник — [официальная документация Zabbix](https://www.zabbix.com/documentation/current/en/manual).

## Как устроен Zabbix
| Часть | Что делает |
|---|---|
| Сервер | Центр системы: принимает данные, проверяет триггеры, рассылает оповещения |
| Агент | Программа на наблюдаемой машине: снимает показатели и читает логи. Пассивный — отвечает на запросы сервера, активный — сам отправляет данные |
| Прокси | Собирает данные в удалённой сети и передаёт серверу |
| База данных | Хранит конфигурацию, историю значений и агрегаты (trends) |
| Веб-интерфейс | Настройка, графики, дашборды, список проблем |

## Основные понятия
| Zabbix | Что это | У нас |
|---|---|---|
| Host | Наблюдаемая машина | Сервис |
| Item | Что и как собирать (одна метрика или один лог-файл) | Метрика / поток логов сервиса |
| Trigger | Логическое выражение над значениями | Правило |
| Problem / Event | Срабатывание триггера и его жизненный цикл | Срабатывание, инцидент |
| Action | Что делать при событии: оповестить, выполнить команду | Оповещение, чат инцидента |
| Template | Набор items и триггеров для многих хостов | Пока не нужно |
| Housekeeper | Удаляет старые данные по сроку хранения | Срок хранения |

## Что из этого следует для нас
Решение спринта 2: не повторяем Zabbix, а расширяем его ([D-004](../architecture/decisions.md)).

- **Берём у Zabbix целиком:** сбор метрик и логов, хранение, триггеры, проблемы, оповещения.
- **Добавляем то, чего у него нет:** разбор причины — кто отклонился первым, доказательства из логов, один инцидент вместо лавины, точность разбора на размеченных сбоях.
- **Что Zabbix даёт для расширения:** коннекторы (поток событий), JSON-RPC API, `history.push`, модули интерфейса, действия. Подробно — [zabbix-integration.md](../architecture/zabbix-integration.md).
