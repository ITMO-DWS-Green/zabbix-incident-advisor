# Бот в Telegram

Бот присылает в чаты команды оповещения о задачах и PR и напоминает о встречах. Это не отдельный сервер: всё работает в GitHub Actions этого репозитория.

| Что | Где |
|---|---|
| Оповещения о событиях GitHub | `.github/workflows/telegram.yml`, `.github/scripts/telegram_notify.py` |
| Напоминания о встречах, команды бота, список чатов | `.github/workflows/meetings.yml`, `.github/scripts/meeting_reminders.py` |
| «Кто что делает» с доски | `.github/scripts/board_status.py` |
| Тесты разбора расписания | `python3 .github/scripts/test_meeting_reminders.py` |

## Как подключить

1. Бот создаётся у @BotFather (`/newbot`), токен — в секрет репозитория `TELEGRAM_BOT_TOKEN`.
2. Бота добавляют в чат как обычного участника. Права администратора не нужны.
3. Через 5 минут бот знает о чате и пишет туда. Каждый, кто не администратор чата, отправляет `/join@имя_бота`, чтобы его тегали перед встречами.

Секреты и переменные (Settings → Secrets and variables → Actions):

| Имя | Обязательно | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота |
| `TELEGRAM_CHAT_ID` | нет | чаты, куда писать всегда, даже если бот о них ещё не узнал: id через запятую, `id:тема` для темы |
| `PROJECT_TOKEN` | нет | токен с правом читать проекты организации (fine-grained: Organization → Projects → Read-only; или classic с `read:project`) — для «кто что делает» с доски |
| `PROJECT_NUMBER` (переменная) | нет | номер доски из адреса `…/orgs/ITMO-DWS-Green/projects/<номер>`; без неё — первая доска организации с задачами этого репозитория |

## Команды

В группе команду пишут с именем бота: `/join@имя_бота`. Без имени Telegram может не передать команду боту. Бот отвечает в течение 5 минут.

| Команда | Где писать | Что делает |
|---|---|---|
| `/github` | в нужной теме | оповещения GitHub — в эту тему |
| `/meetings` | в нужной теме | напоминания о встречах — в эту тему; без команды — туда же, куда оповещения GitHub |
| `/join` | в чате | тегать меня за 15 минут до встреч |
| `/leave` | в чате | не тегать меня |
| `/off` | в чате | не писать в этот чат вообще |
| `/on` | в чате | снова писать в этот чат |

Тема — раздел в группе с темами. Без команды бот пишет в общий раздел. `/github` или `/meetings` в общем разделе возвращают туда.

## Когда бот пишет

Оповещения GitHub уходят сразу после события, задержка — несколько секунд.

| Событие | Сообщение |
|---|---|
| Задача создана | 🆕 Новая задача (📅 Новая встреча — для метки `встреча`) |
| Задача закрыта | ✅ выполнена или 🚫 закрыта как неактуальная |
| Задача открыта снова | ↩️ |
| Задачу взяли или назначили | 👤 |
| Комментарий в задаче или PR | 💬 с началом текста |
| PR открыт | 🔀 нужно ревью, или 📝 черновик |
| PR готов к ревью, запрошено ревью | 🔀, 👀 с именем ревьюера |
| PR слит или закрыт | 🟣 или ✖️ |
| Ревью | 👍 одобрил, ✋ просит доработать, 💬 ревью с текстом |
| CI упал в PR | ❌ |

Бот молчит, когда меняют метки, milestone или текст задачи, пушат коммиты в PR, CI прошёл успешно, оставили пустое ревью.

## Встречи

Встреча — открытая задача с меткой `встреча`: New issue → **Встреча**. Поля: когда, длительность, ссылка, кто участвует, повестка. Закрыли задачу — напоминаний нет. Изменили описание — бот берёт новое через 5 минут.

### Напоминания

| Когда | Что в сообщении |
|---|---|
| за сутки | 📅 время, участники, ссылка, повестка |
| за час | ⏰ время, участники, ссылка |
| за 15 минут | 🔔 ссылка, «кто что делает», теги участников |
| встреча без времени | накануне в 12:00 и в день встречи в 9:00 |

**Кого тегает.** Администраторов чата и всех, кто написал `/join`. Telegram не отдаёт боту список всех участников группы, поэтому тегнуть всех разом нельзя. Пользователя без юзернейма бот тегает по имени через ссылку — такое упоминание работает, если человек сам писал в чат.

**Протокол.** Если в задаче встречи заполнено поле «Протокол» (кого отметить, например `@AVEroshkin`), в начале встречи бот присылает протокол и сохраняет его комментарием в задаче:

```
@AVEroshkin
Протокол 30.10.2026:
Присутствовали:
Катан Михаил
…
Распределение по задачам:
Михаил Катан:
1) Spike: пересогласовать требования под расширение Zabbix — https://github.com/ITMO-DWS-Green/zabbix-incident-advisor/issues/1
…
```

Присутствовавшие по умолчанию — вся команда из `.github/team.json`; задачи — открытые задачи, где человек исполнитель: название и ссылка. Состав команды и порядок меняются в `team.json`.

**Кто что делает.** С доски — карточки этого репозитория в колонках «In progress» и «In review», по исполнителям; в заголовке «(с доски)». Без `PROJECT_TOKEN` или если доска недоступна — открытые назначенные задачи и открытые PR; в заголовке «(по назначенным задачам и открытым PR)». Если не получилось ни то ни другое, напоминание уходит без этого блока.

### Как записывать «Когда»

Время московское.

| Что нужно | Что написать |
|---|---|
| каждую неделю | `каждый вторник 12:15`, `по пятницам 16:00` |
| несколько дней | `пн, чт 19:00` |
| по будням, каждый день | `по будням 10:00`, `каждый день 9:30` |
| через неделю | `каждые 2 недели по пятницам 16:00 с 06.11.2026`, `раз в две недели вт 12:15 с 03.11.2026` |
| один раз | `05.11.2026 18:00` |
| дата есть, времени нет | `27.11.2026` |

Встречу перенесли один раз — поменяйте время в задаче и после встречи верните, или заведите отдельную разовую встречу.

### Как бот понимает расписание

Нейросети нет — скрипт ищет в тексте шаблоны:

- **время** — `12:15` или `12.15`;
- **дата** — `27.11.2026`;
- **день недели** — по началу слова: «вт», «вторник», «вторникам» → вторник; «пт», «пятница», «по пятницам» → пятница;
- **«по будням»** — пн–пт; **«каждый день»**, **«ежедневно»** — все дни;
- **«каждые N недели»**, **«раз в две недели»** — интервал; **«с ДД.ММ.ГГГГ»** — от какой даты считать недели.

Остальные слова пропускаются. Из найденного скрипт вычисляет ближайшую встречу и, если до неё меньше суток, часа или 15 минут, отправляет напоминание. Если в записи нет ни дня недели, ни даты, напоминаний не будет, а в логе запуска «Встречи» появится «не понял расписание…».

## Как устроено

- **Список чатов.** У Telegram нет способа спросить «в каких чатах бот». Бот узнаёт о чатах из своих обновлений: «бота добавили», сообщения, команды. Обновления читает только workflow «Встречи» раз в 5 минут, по одному запуску за раз, и подтверждает прочитанные — поэтому каждая команда обрабатывается ровно один раз. Telegram хранит неподтверждённые обновления 24 часа.
- **Память бота** — кэш GitHub Actions: `chats.json` (чаты, темы, `/join`, выключенные чаты) и `sent.json` (какие напоминания уже отправлены, хранится неделю). Если кэш пропадёт, бот заново узнает чаты только из новых событий; темы и `/join` придётся отправить заново.
- **Чат убрали.** Удалили бота из чата или отправка вернула 403 — чат выпадает из рассылки. Группа стала супергруппой — бот переходит на новый id сам.
- **Расписание GitHub неточное.** Запуск «каждые 5 минут» GitHub может задержать на несколько минут, поэтому напоминание «за 15 минут» иногда приходит за 10–14. Окно «за 15 минут» — 20 минут до начала.
- **Вручную** — Actions → «Встречи» → Run workflow: обработать команды и напоминания сразу.

## Если что-то не так

| Проблема | Что проверить |
|---|---|
| Бот не отвечает на команду | Подождать 5 минут или запустить «Встречи» вручную; писать с именем бота; токен в `TELEGRAM_BOT_TOKEN` от того же бота; на боте нет вебхука — в `https://api.telegram.org/bot<токен>/getWebhookInfo` поле `url` пустое |
| Нет пушей при упоминании | Открыт Telegram на компьютере — на телефон пуши не идут; чат или тема без звука — включить «Уведомлять об упоминаниях» |
| Кого-то не тегает | Человек не администратор и не писал `/join` |
| Нет напоминания | Задача открыта и с меткой `встреча`; «Когда» записано по примерам; в логе «Встречи» нет «не понял расписание» |
| «Кто что делает» не с доски | `PROJECT_TOKEN` с правом Projects: Read; токен одобрен организацией; задачи репозитория добавлены на доску; при нескольких досках задан `PROJECT_NUMBER` |
