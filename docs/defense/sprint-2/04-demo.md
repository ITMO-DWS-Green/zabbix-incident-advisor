## Если показывать живой стенд

Команды из корня репозитория:

```bash
docker compose --profile stand up -d --build
python3 infra/setup/e2e_test.py
```

Адреса:

- Zabbix: `http://localhost:8070` → Monitoring → Incident advisor;
- панель test-server: `http://localhost:8090`;
- Advisor API: `http://localhost:8095`.

После запуска стенду нужно дать прогреть историю. Ожидаемая задержка анализа задаётся `ADVISOR_ANALYSIS_DELAY` и по умолчанию равна 60 секундам. Для репетиции можно использовать сокращённую задержку, как в CI, но её значение нужно явно сообщить ведущему.

Порядок показа: сначала включить сбой на test-server, затем открыть Problems в Zabbix, после появления результата перейти в Incident advisor и показать карточку. Живой показ должен укладываться в 2–3 минуты; ожидание запуска и анализа заранее выполняется до начала выступления.

## Резервный переход

Если живой стенд не готов или задержка анализа превышает регламент, открыть `assets/demo-sprint-2.mp4` и начать с начала. Ведущий проговаривает: «Это тот же сквозной сценарий в записи: Zabbix получает проблемы, Incident advisor объединяет их и показывает результат анализа». После финального кадра вернуться к карточке Incident advisor или к слайду с архитектурой.

Видео — резервная демонстрация экранного сценария. Реальная доставка Telegram, точность на выборке и воспроизводимость запуска в текущем файле отдельно не измеряются.

## Сброс стенда

```bash
docker compose --profile stand --profile ollama down -v
```

Сброс удаляет контейнеры и тома с данными Zabbix и Advisor.
