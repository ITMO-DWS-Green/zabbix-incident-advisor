# Единый язык

Эти слова одинаково используют заказчик, аналитики и разработчики — в разговорах, задачах, интерфейсе и коде. Нет термина или его понимают по-разному — сначала дополняем этот файл.

**Главная цепочка:** источник присылает записи лога и значения метрик → обнаружение даёт срабатывания → связанные срабатывания объединяются в инцидент → у инцидента есть подозрительные сервисы, объяснение и ответственная команда → создаётся чат инцидента.

Два правила, которые чаще всего нарушают:
- «Алерт» не говорим. Это либо **срабатывание** (система что-то заметила), либо **оповещение** (сообщение человеку).
- «Ошибка» — это уровень записи лога, а не сбой. Сбой в системе — **сбой**, его последствие для нас — **инцидент**.

## Данные

| Термин | Что значит | Не путать |
|---|---|---|
| Сервис | Приложение, за которым наблюдаем; в генераторе — один из имитируемых сервисов | — |
| Источник | Откуда приходят данные: генератор или внешний API | Не «агент» — агентов в MVP нет |
| Запись лога | Одна строка лога: время, сервис, уровень, сообщение, идентификатор запроса | Не «событие» |
| Уровень лога | ERROR, WARN, INFO и т. д. | Не важность инцидента |
| Метрика | Числовой показатель сервиса во времени: задержка, доля ошибок, число запросов | Не «лог» |
| Значение метрики | Одно измерение: метрика, сервис, время, число | — |
| Единый формат | Общая схема записи лога и значения метрики для всех источников | — |
| Временная шкала | Общее время, к которому привязаны все данные | — |
| Потоковый приём | Данные приходят в реальном времени | — |
| Офлайн-анализ | Анализ данных, загруженных из файла | — |

## Генератор и разметка

| Термин | Что значит | Не путать |
|---|---|---|
| Генератор | Имитирует несколько взаимодействующих сервисов и создаёт их логи и метрики | — |
| Сценарий | Описание прогона: какие сервисы, какие сбои, когда | — |
| Сбой | Нарушение работы сервиса, внедрённое по сценарию: рост задержки, всплеск ошибок, падение, утечка ресурса | Не «инцидент» |
| Тип сбоя | Вид сбоя из списка выше | — |
| Разметка | Правда о внедрённом сбое: начало, конец, тип, сервис-источник. Эталон для оценки качества | Не результат обнаружения |
| Сервис-источник | Сервис, в котором сбой начался. В разметке известен точно; для инцидента система его предполагает — это первый в списке подозрительных сервисов | — |

## Обнаружение

| Термин | Что значит | Не путать |
|---|---|---|
| Аномалия | Поведение данных, заметно отличающееся от обычного | Не «сбой»: аномалия — то, что видим, сбой — что случилось |
| Правило | Условие + длительность, например «доля ошибок > 5% дольше 1 минуты» | — |
| Статистический порог | Граница нормы, вычисленная из истории метрики | Не задаётся вручную |
| ML-модель | Модель машинного обучения, которая находит аномалии на тех же данных | — |
| Подход | Способ обнаружения: «правила и пороги» или «ML» | — |
| Срабатывание | Факт, что подход заметил аномалию: время, сервис, подход, метрика, сила отклонения | Не «алерт», не «инцидент» |

## Инцидент и реакция

| Термин | Что значит | Не путать |
|---|---|---|
| Инцидент | Группа связанных срабатываний с одной причиной | Одно срабатывание — ещё не инцидент |
| Объединение | Сборка связанных срабатываний в инцидент, чтобы не было дублирующих оповещений | — |
| Подозрительный сервис | Сервис, который может быть причиной инцидента; список ранжирован от самого вероятного | — |
| Объяснение | Отклонившиеся метрики и примеры характерных записей лога по инциденту | Гипотеза, а не диагноз |
| Команда | Группа людей, отвечающая за сервисы | Не наша команда разработки |
| Справочник «сервис — команда» | Кто отвечает за какой сервис | — |
| Ответственная команда | Команда сервиса-источника инцидента по справочнику | — |
| Чат инцидента | Чат в мессенджере, созданный системой: ответственные + описание инцидента | — |
| Оповещение | Сообщение человеку об инциденте | Не «срабатывание» |

## Оценка качества

Считается по разметке на одних и тех же сценариях для обоих подходов.

| Термин | Что значит |
|---|---|
| Precision (точность) | Какая доля найденных инцидентов — настоящие сбои |
| Recall (полнота) | Какая доля настоящих сбоев найдена |
| F1 | Одно число, балансирующее точность и полноту |
| Доля ложных тревог | Сколько найденных инцидентов не соответствуют ни одному сбою |
| Задержка обнаружения | Сколько прошло от начала сбоя до первого срабатывания |
