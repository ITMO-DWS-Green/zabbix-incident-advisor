# Критерии приёмки

Статус: **черновик**, согласовать с заказчиком ([задача #1](https://github.com/ITMO-DWS-Green/log-collector/issues/1)). Без них непонятно, когда остановиться и перестать дорабатывать.

## Как проверяем
Поднимаем тестовый стенд, запускаем генератор с набором сценариев сбоев и смотрим результат.

## Предлагаемые критерии
- [ ] Каждый внедрённый сбой сохраняется с разметкой (начало, конец, тип, сервис-источник).
- [ ] Настроенные правила дают срабатывания на соответствующих сбоях.
- [ ] ML-модель находит сбои, для которых правила не настроены.
- [ ] На один сбой создаётся один инцидент, без дублирующих оповещений.
- [ ] Для каждого подхода посчитаны precision, recall, F1, доля ложных тревог и задержка обнаружения.
- [ ] В списке подозрительных сервисов настоящий сервис-источник входит в первые 3.
- [ ] У инцидента есть объяснение: отклонившиеся метрики и примеры записей лога.
- [ ] При инциденте создаётся чат с ответственной командой и описанием.
- [ ] В веб-интерфейсе видны список инцидентов, карточка и результаты сравнения.

Пороговые значения (например, «recall не ниже X») — открытый вопрос к заказчику.
