# Нефункциональные требования

Статус: **черновик** ([#38](https://github.com/ITMO-DWS-Green/zabbix-incident-advisor/issues/38)). Значения — предложение команды, утверждаем с заказчиком. Где значение уже заложено в каркас — указана настройка.

| ID | Тема | Требование | Значение | Где в каркасе | Источник |
|---|---|---|---|---|---|
| NFR-01 | Совместимость | Работает с Zabbix 7.0 LTS без изменения его ядра: только коннекторы, API, модуль интерфейса, действия | Zabbix 7.0 | образы `zabbix/*:alpine-7.0-latest` | |
| NFR-02 | Развёртывание | Стенд (Zabbix, test-server, наш сервис, модуль) поднимается одной командой на чистой машине по README | `docker compose --profile stand up -d --build` | `compose.yaml`, CI проверяет | |
| NFR-03 | Скорость разбора | Время от события о проблеме до комментария в Zabbix | ≤ 60 с — см. [вопрос](open-questions.md) | `ADVISOR_ANALYSIS_DELAY`, 60 с | предложено |
| NFR-04 | Окно анализа | Сколько истории перед проблемой смотрим при разборе | 15 мин, настраивается | `ADVISOR_ANALYSIS_LOOKBACK` | предложено |
| NFR-05 | Нагрузка | Стенд: 4 сервиса × ~10 метрик раз в 5–30 с + логи до 50 строк/с на сервис; сервис справляется без отставания | замер в спринте 3 | `historyLimit`, `maxItemsPerHost` | |
| NFR-06 | Надёжность приёма | Отвечаем коннектору 200–204; если сервис был недоступен, пропуски дозапрашиваем через `problem.get` и `history.get`; незавершённые разборы продолжаются после перезапуска | — | `AnalysisScheduler.resumePending`, догон — [#41](https://github.com/ITMO-DWS-Green/zabbix-incident-advisor/issues/41) | |
| NFR-07 | Хранение | Своя БД хранит только инциденты, разборы, разметку, оценки и журнал LLM; метрики и логи остаются в Zabbix | инциденты — 90 дней | PostgreSQL, [#36](https://github.com/ITMO-DWS-Green/zabbix-incident-advisor/issues/36) | предложено |
| NFR-08 | Права | Токен API сервиса: чтение нужных групп хостов, запись комментариев к проблемам; без прав администратора | — | на стенде — токен Admin, боевой вариант — [#34](https://github.com/ITMO-DWS-Green/zabbix-incident-advisor/issues/34) | |
| NFR-09 | Данные наружу | Логи и метрики не уходят во внешние сервисы. LLM — только с маскированием, с журналом и с разрешения заказчика | по умолчанию LLM выключена | `ADVISOR_LLM_PROVIDER=stub`, `Masker`, таблица `llm_audit` | вопрос заказчику |
| NFR-10 | Честная оценка | Разбор не видит разметку и элементы, по которым видно включённый сценарий (`testserver.status`, `testserver.scenario`) | — | разметка только в `analysis-evaluation`; текстовые элементы без тега `component: logs` в разбор не попадают | |
| NFR-11 | Качество кода | Сборка и тесты в CI на каждый PR, тесты на логику разбора; сквозная проверка на живом Zabbix | — | `.github/workflows/ci.yml` | |
| NFR-12 | Безопасность интеграции | Коннектор приходит с Bearer-токеном, модуль ходит в сервис через PHP-прокси с секретом; JS не обращается к сервису напрямую | — | `SecurityFilter`, `ServiceClient.php` | |

Когда значение утверждено — пишем в «Источник», кто и когда.
